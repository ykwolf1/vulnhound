# vulnhound MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 vulnhound MVP——输入地址，AI 在容器沙箱自由测试，流量全量审计，产出证据可溯源的结构化报告；对 DVWA 端到端跑通。

**Architecture:** 三件套：审计代理（宿主机，记录+三元组拦截）→ Agent 容器（命令执行环境，出口仅指代理）→ LLM 循环（宿主机驱动，命令经 docker exec 进容器）。薄后端 FastAPI + SSE；前端由原型演化。

**Tech Stack:** Python 3.12 / FastAPI / httpcore(asyncio 手写代理) / Docker(python:3.12-slim+curl) / DeepSeek(OpenAI 兼容) / 原生前端(SSE)。

**Spec:** docs/spec.md（§3 范围、§6 契约为验收基准；prototype/index.html 为交互基准）。

- LLM：DeepSeek（`LLM_API_KEY` 环境变量，.env 不入库）；**单测一律 FakeLLM，零网络零真实容器**。

- 薄纪律：不引入数据库/ORM/前端框架/任务队列；文件即状态（`sessions/<id>/` 目录）。

### Task 2: 审计代理（TDD）

**Files:**
- Create: `pyproject.toml`（deps: fastapi, uvicorn, httpx；dev: pytest, pytest-asyncio, ruff）、`proxy/__init__.py`、`proxy/audit_proxy.py`
- Test: `tests/test_proxy.py`

**Interfaces:**
- Produces:
  - `AuditTarget = tuple[str, int, str]`（host, port, scheme）
  - `class AuditProxy: def __init__(self, allowed: AuditTarget, record_path: Path)`；`async def start(self) -> int`（返回监听端口）；`async def stop(self)`
  - 记录格式（JSONL，每行）：`{"request_id": int, "ts": iso, "method": str, "url": str, "status": int|None, "req_body": str(截断4KB), "resp_body": str(截断64KB), "blocked": bool, "block_reason": str|null}`
  - 行为：HTTP 请求（绝对 URL）→ 三元组匹配放行并转发、记录；不匹配 → 记录 blocked + 返回 403；CONNECT 一律 403（MVP 仅 HTTP）
- 单测（真 socket，本机 127.0.0.1 起一个假目标 http server + 代理）：
  1. 放行匹配请求并转发，记录含 request_id=1、resp_body
  2. 拦截 host 不同（evil.com）→ blocked 记录 + 客户端收到 403
  3. 拦截 port 不同（目标 :80，请求 :22）→ blocked
  4. request_id 单调递增
- [ ] TDD 四用例 → 实现 → Commit `feat: audit proxy with triple whitelist and jsonl recording`

### Task 3: Agent 容器与执行器

**Files:**
- Create: `agent/Dockerfile`（FROM python:3.12-slim + curl + 安装 requests）、`agent/runner.py`
- Test: `tests/test_runner.py`（monkeypatch docker 调用，零真实容器）

**Interfaces:**
- Produces:
  - `class Sandbox: def __init__(self, proxy_port: int)`；`async def start(self)`（`docker run -d --rm vh-agent sleep infinity`，env `HTTP_PROXY=http://host.docker.internal:{port}`、`HTTPS_PROXY` 同）；`async def exec(self, cmd: str, timeout: int = 60) -> ExecResult{stdout, stderr, returncode}`（`docker exec` 执行）；`async def stop(self)`
  - `SandboxNotAvailableError`（docker 不可用/镜像缺失时明确报错）
- 单测：monkeypatch `asyncio.create_subprocess_exec`——断言 docker run 参数含 proxy env；exec 返回解析；stop 调 docker stop。
- [ ] Dockerfile + build 镜像（本机一次真实 build 验证）→ TDD runner → Commit `feat: agent sandbox container and executor`

### Task 4: LLM 循环（TDD，FakeLLM）

**Files:**
- Create: `agent/llm.py`（DeepSeek 客户端，按 Task 1 选定协议封装）、`agent/loop.py`、`agent/schema.py`、`agent/prompt.py`
- Test: `tests/test_loop.py`

**Interfaces:**
- Consumes: Task 1 协议决策、Task 3 `Sandbox.exec`。
- Produces:
  - `Verdict`（pydantic）：`{findings: [{title, severity: Literal[high,medium,low], rationale(max300), evidence: list[int]}], discarded: [{title, reason}]}` + `stopped_reason: completed|step_cap|no_progress|llm_error|null`
  - `class FakeLLM`（测试）：`__init__(script: list[str])` 按序返回
  - `async def run_agent(llm, sandbox, target_url, creds, max_steps=20) -> tuple[Verdict, list[StepEvent]]`；`StepEvent = {n, tag: observe|act|hypo|verify|conclude, text, cmd|null, result|null}`
  - 无进展检测：连续 3 步 cmd 相同或 stdout 相似度 >0.9 → stopped_reason=no_progress
  - evidence 校验：Verdict.evidence 引用不存在 request_id → 追加纠错消息重试 1 次，仍败 → llm_error
- 单测（FakeLLM 脚本 + FakeSandbox）：正常完成（结论引用合法 id）/ 步数触顶 / 无进展触发 / evidence 非法两次 → llm_error。
- [ ] TDD 四用例 → 实现 → Commit `feat: agent loop with verdict schema and no-progress detection`
