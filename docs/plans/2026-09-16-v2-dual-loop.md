### Task 2: run_agent_v2 双层循环（TDD）

**Files:**
- Create: `agent/loop_v2.py`
- Test: `tests/test_loop_v2.py`

**Interfaces:**
- Consumes: Task 1 Direction/SWITCH_TOOL/CHEAT_SHEET；MVP 的 Verdict/StepEvent/EXEC/REPORT/无进展检测逻辑（从 loop.py 复用或提取公共函数——**裁定：提取 `agent/progress.py` 放相似度检测与步进工具函数，v1/v2 共用**）。
- Produces:
  - `StepEvent.tag` 扩展 `"direction"`（v1 类型注解兼容：Literal 加值）
  - `async def run_agent_v2(llm, sandbox, target_url, creds, max_steps=100, max_steps_per_direction=15) -> tuple[Verdict|None, list[StepEvent], str]`
  - 行为（spec §3.3 逐条）：
    - switch_direction 调用 → current.outcome 记录（current_outcome 参数）、append directions、建新 Direction、**切换时注入 CHEAT_SHEET 为 user 消息**、emit StepEvent(tag="direction", text=f"切换: {old}→{new}")
    - 方向预算：current.steps_used >= 15 → 注入提醒 user 消息"此方向预算尽，请 switch 或 submit"（不强制切——模型可选择提交）
    - 无进展（复用 progress 检测）→ **强制 switch**：注入"连续无新信息，必须 switch_direction"
    - 触顶收卷：同 MVP 强制收卷轮 + Verdict 附 directions 元数据（report 里可见方向轨迹）
    - 返回 directions 列表附在 events 末尾（tag="direction" 的汇总事件）
- 单测（FakeLLM 脚本 ≥7 用例）：正常双方向切换+提交 / 方向预算尽提醒注入 / 无进展强制切换 / 速查卡注入时机（切换后第一条 user 消息含 CHEAT_SHEET）/ 强制收卷含方向汇总 / submit 直接返回（v1 兼容路径）/ max_steps_per_direction=0 边界。
- Commit `feat: dual-loop run_agent_v2 with direction management`
